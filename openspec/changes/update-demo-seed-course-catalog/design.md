# Update Demo Seed Course Catalog — Design

## Context

The demo seed (`prisma/seed/`) currently seeds 35 fabricated courses via `courseDefinitions` in `prisma/seed/fixtures/academic-structure.ts`. The official ACD curriculum — 102 courses — is delivered as `docs/acd_programs_demo_seed_recommended_expanded.csv` (untracked, provided by stakeholders). Courses are consumed downstream by course assignments + roster memberships, CILOs, course-bound evaluations, responses, and curriculum baseline DRAFT generation (`generate-baseline.ts`), which derives `CurriculumCourse` placements from `Course.default_*` fields (ADR 0013).

Constraints:
- `courses.code` is globally unique (`prisma/models/course-assignments.prisma:59`).
- Seed runners look up courses by code from `cMap` and fail loudly (`requireCourseAssignment`, `findUniqueOrThrow`) on stale codes — a natural safety net.
- Baseline generator skips non-SUMMER courses without a term (`generate-baseline.ts:61`).
- `prisma/seed` must remain idempotent (upsert-based); `pnpm test` must not touch a hosted DB; DB invariant suites are opt-in.

## Goals / Non-Goals

**Goals:**
- Demo catalog reflects the real ACD curriculum (102 courses, 5 GE + 97 program-specific, 6 programs, majors for BSED/BSBA).
- All downstream seed fixtures remapped; seed stays green and idempotent.
- Every course baseline-eligible (complete placement defaults).

**Non-Goals:**
- No schema/migration/RLS/API changes.
- No runtime CSV parsing in seed (fixture is compiled and typed).
- No curriculum version seeding (baselines are generated by the service, unchanged).
- No changes to user/period/deployment/response fixtures beyond course-code references.

## Decisions

### D1: Transform CSV → TS fixture at authoring time, not seed time
`courseDefinitions` becomes the compiled, typed, linted representation of the CSV. Rationale: seed stays deterministic, no filesystem dependency at runtime, normalizations are reviewable in diff. Alternative rejected: reading the CSV in `seed-foundation.ts` — breaks when CSV moves/renames, untyped strings, normalization logic lives in seed path.

### D2: Normalize codes by stripping spaces
`IT 101` → `IT101`, `HM-E 4` → `HM-E4`, `NSTP 1` → `NSTP1`. Rationale: matches every existing code, snapshot, and test string; avoids whitespace-sensitive bugs in snapshots/URLs. Uniqueness re-verified post-normalization (no collisions found; script asserts before commit). CSV stays canonical human reference.

### D3: Fill blank terms with semester↔term rule
`FIRST`→`FIRST_TERM`, `SECOND`→`SECOND_TERM`, `SUMMER`→`null`. Rationale: baseline generator excludes non-SUMMER courses without term; stakeholder-approved "sensible defaults" so all courses land in baseline DRAFTs. Rule documented in fixture comment.

### D4: Full replacement including IT-OD-401
All fabricated courses removed; outline-defense demo course replaced by `ITRES1` (Capstone Project 1 — the capstone proposal phase IS the outline defense). Rationale: stakeholder decision; CSV is the only truth. `verify-production-auth-boundary` marker string updated (string-only, no DB dependency).

## Risks / Trade-offs

- [Stale code references throw at seed time] → Loud failure is by design; remap table + final grep sweep for all old codes (`IT-OD-401|GEGS101|EDUC301|…`) before merge.
- [ENG201 semantics change (BSED→BEED) surprises seeded-membership DB test] → Test only asserts invariants on the assignment, code-agnostic; fixture switches `programCode` to BEED.
- [CSV edits drift from fixture] → Fixture comment names the source CSV; new unit test pins uniqueness/placement/major-reference invariants so drift surfaces in CI.
- [Baseline DRAFTs gain 102 courses — UI overload] → Baselines are operator-edited; superset is the intent (real catalog), not a regression.

## Migration Plan

1. Fix CSV `PRAC-BA` row (add trailing comma).
2. Rewrite `courseDefinitions` (102 entries, grouped by program, comment documenting normalization + term-fill rules).
3. Remap fixtures: `course-assignments.ts`, `outcomes.ts`, `evaluations.ts`, `responses.ts`, `runners/seed-evaluations.ts` (codes + deployment names), boundary marker test.
4. Add `src/__tests__/seed/academic-structure-fixture.test.ts` invariants test.
5. Verify: `pnpm lint`, `pnpm build`, `pnpm test`; opt-in DB suites with `RUN_DATABASE_INTEGRATION_TESTS=1` against disposable DB; `pnpm db:seed` idempotency (run twice); baseline generation spot check.

Rollback: revert commit; seed upserts make re-running safe in either direction.
