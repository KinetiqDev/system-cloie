# System CLOIE Alpha Testing Evidence Report

## Executive finding

Technical alpha evidence was collected from the current working tree, disposable local infrastructure, repository test configuration, GitHub Actions records, and the connected Google Docs manuscript and testing records. The current build is **not ready for an unqualified alpha pass or final acceptance**.

The current checkout is `main` at commit [`9a397c8`](https://github.com/KinetiqDev/system-cloie/commit/9a397c802d9117234c56306d02d3006a3916f08d). A syntax error in `src/features/analytics/services/general-education-analytics.ts:352` prevents the General Education analytics service from transforming. That failure caused the full Vitest run, the Node Vitest shard, and the production build to fail. The DOM shard, tooling-integration suite, target-safety check, and database-suite discovery check passed.

The latest available CI records were created for the preceding merge commit [`b08c77a`](https://github.com/KinetiqDev/system-cloie/commit/b08c77a8da58c69b6c5456c3a49e1028e7517539), not the current `9a397c8` checkout. Those records provide useful prior-build evidence but do not prove the current checkout is green. The latest main-branch Quality Checks run passed static checks, both unit shards, production build, and database integration, but failed Browser E2E. The scheduled deep run passed Chromium, live-RLS database integration, tooling integration, production-auth-boundary, and demo-reset isolation checks, but failed Firefox and WebKit.

The connected Google Docs technical manuscript reports an earlier pre-final automated result of 3,878 passed out of 3,879 executed tests and a human beta cycle with 12 participants across five stakeholder groups. Those are prior manuscript claims, not results of this alpha execution. The same manuscript states that internal alpha testing preceded beta but does not contain a consolidated alpha total. No human alpha participant record, signed Appendix G-2 validation, or Appendix G-4 acceptance record was found in the available evidence.

## 3. Alpha execution environment

### 3.1 Local execution

- OS: Linux x64.
- Local runtime: `node --version` returned `v26.8.1`; repository CI workflow specifies Node.js 22. The local runtime and CI runtime are therefore different and results are not treated as byte-for-byte environment-equivalent.
- pnpm: `10.30.3`.
- Playwright: `1.62.1`.
- Local Supabase CLI Docker stack: running and healthy before the disposable reset.
- Local database target: `postgresql://127.0.0.1:54322/postgres`, verified by `pnpm verify:database-target` as a disposable target.
- Local fixture: reset and reseeded with `pnpm supabase:reset && pnpm db:seed` before the final local E2E attempt.
- Local browser mode: Next.js development server on port 3100; this is exploratory alpha evidence, not accepted production-browser evidence.

No hosted or shared database was used by the local runs. The local reset is destructive only to the disposable local Supabase stack.

### 3.2 CI execution

CI uses disposable PostgreSQL 16 service containers, canonical migrations, deterministic seed data, and signed CI test authentication. The repository disables Playwright retries for required checks. A red-then-green run is therefore not silently counted as a clean pass.

The CI records in this report are linked to their exact run and commit. Full job logs were requested through the available GitHub interfaces, but the public job-log responses reported that logs were unavailable without a `GITHUB_TOKEN`/`GH_TOKEN` or because the logs had expired. The run pages, job conclusions, step-level failure location, and artifact-upload steps remain verifiable.

## 9. Interpretation for Chapter 5

### 5.3 Testing and quality evaluation

The current technical evidence supports a mixed conclusion. DOM component coverage and tooling integration are green. The full default suite and production build are blocked by a current source parse error. The local database run is invalid as a product verdict because the disposable environment was not prepared with the CI RLS test role, while the corresponding CI live-RLS jobs passed. Browser evidence is also mixed: the prior pull-request Chromium run passed; the latest main-branch Browser E2E run failed; the scheduled Chromium matrix passed while Firefox and WebKit failed.

The correct claim is therefore **substantial but not complete verification**, not “all tests passed.”

### 5.4 Alpha/beta/user validation

This activity supplies internal technical alpha evidence. It does not replace human alpha, beta, UAT, or stakeholder acceptance. The Google Docs manuscript supplies prior beta evidence with 12 participants and 99 quantitative task ratings, but it also records incomplete retesting, unrepresented stakeholder roles, and absent signed acceptance. Those limitations remain open.

### 5.5 Limitations

The evidence does not establish production performance, Google OAuth exchange latency, physical-device behavior, screen-reader behavior, disaster recovery, or current-HEAD cross-browser compatibility. CI job pages expose failure locations but complete logs were unavailable through the unauthenticated public response. The local E2E run used development authentication and is not production evidence.
