# System CLOIE Alpha Testing Evidence Report

## Executive finding

Technical alpha evidence was collected from the current working tree, disposable local infrastructure, repository test configuration, GitHub Actions records, and the connected Google Docs manuscript and testing records. The corrected working tree passes the unit, tooling, build, and gated database checks. It is **not ready for an unqualified alpha pass or final acceptance** because 4 of 48 browser tests still fail and no human acceptance record exists.

The evidence target is branch `fix/analytics-period-labels`, based on commit [`eeccf8d`](https://github.com/KinetiqDev/system-cloie/commit/eeccf8de343409e47879de4d9262ea00569355bc), with uncommitted source, test, and configuration changes present during the corrected runs. The base commit still contains the malformed General Education analytics expression found during the first run; the working-tree changes correct it. On that working tree, `pnpm test` passed 430 files and 3,914 tests, `pnpm build` passed, all 15 database suites passed with 209 tests, and Playwright passed 44 of 48 tests.

The four browser failures were:

1. the filtered-empty Responses navigation scenario;
2. the Dean Learning Outcomes selected-period scenario; and
3. the desktop and mobile Program Head visual baselines.

The latest available CI records were created for the preceding merge commit [`b08c77a`](https://github.com/KinetiqDev/system-cloie/commit/b08c77a8da58c69b6c5456c3a49e1028e7517539), not the current `eeccf8d` base or its working-tree changes. Those records provide prior-build evidence but do not prove the current snapshot is green. The latest main-branch Quality Checks run passed static checks, both unit shards, production build, and database integration, but failed Browser E2E. The scheduled deep run passed Chromium, live-RLS database integration, tooling integration, production-auth-boundary, and demo-reset isolation checks, but failed Firefox and WebKit.

The connected Google Docs technical manuscript reports an earlier pre-final automated result of 3,878 passed out of 3,879 executed tests and a human beta cycle with 12 participants across five stakeholder groups. Those are prior manuscript claims, not results of this alpha execution. The same manuscript states that internal alpha testing preceded beta but does not contain a consolidated alpha total. No human alpha participant record, signed Appendix G-2 validation, or Appendix G-4 acceptance record was found in the available evidence.

The corrected results came from an uncommitted working tree. They are not presented as committed CI results.

## 3. Alpha execution environment

### 3.1 Local execution

- OS: Linux x64.
- Local runtime: Node.js `v26.8.1`. The repository CI workflow specifies Node.js 22, so local and CI results are not byte-for-byte environment equivalents.
- pnpm: `10.30.3`.
- Playwright: `1.62.1`.
- Local Supabase CLI Docker stack: running before the disposable reset.
- Local database target: `postgresql://127.0.0.1:54322/postgres`, verified as disposable by `pnpm verify:database-target`.
- Local fixture: reset and reseeded with `pnpm supabase:reset && pnpm db:seed` before the corrected E2E attempt.
- Local browser mode: Next.js development server on port `3110`. This is exploratory alpha evidence, not accepted production-browser evidence.

The database test runner prepared the `test_authenticated` role before executing the gated suites. No hosted or shared database was used by the local runs. The local reset is destructive only to the disposable local Supabase stack.

### 3.2 CI execution

CI uses disposable PostgreSQL 16 service containers, canonical migrations, deterministic seed data, and signed CI test authentication. The repository disables Playwright retries for required checks. A red-then-green run is therefore not silently counted as a clean pass.

The CI records in this report are linked to their exact run and commit. Complete job logs were requested through the available GitHub interfaces, but the public job-log responses reported that logs were unavailable without a `GITHUB_TOKEN` or `GH_TOKEN`, or because the logs had expired. Run pages, job conclusions, failure locations, and artifact-upload steps remain verifiable.
